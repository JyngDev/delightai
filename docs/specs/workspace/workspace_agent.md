# Workspace Home 정보 설계 지침 (for Claude Code)

> **문서 유형**: 정보 구조 지침서 (Information Architecture Guide)
> **대상 독자**: Claude Code
> **작성일**: 2026-04-22
> **이 문서의 범위**: "어떤 정보를 보여줄 것인가"에 집중. UI 디자인·스타일은 Claude Code 자율 판단.

---

## 🎯 0. 이 화면의 목적

**Workspace Home은 팀 단위 Agent 운영 허브다.**

단순히 Agent 목록을 나열하는 페이지가 아니다. 다음 세 가지 역할을 동시에 수행해야 한다.

1. **모니터링**: 이 팀의 Agent들이 전반적으로 건강한가?
2. **탐색·진입**: 작업할 Agent를 빠르게 찾아 들어갈 수 있는가?
3. **관리**: Agent를 만들고 편집·삭제할 수 있는가?

이 세 역할이 **한 화면에서 충돌하지 않도록** 정보를 배치하는 것이 핵심이다.

---

## 🧩 1. 페이지를 구성하는 정보 블록

Workspace Home은 4개의 정보 블록으로 구성된다. 각 블록은 독립된 목적을 가진다.

| 블록              | 목적                              | 주 사용자의 질문           |
| ----------------- | --------------------------------- | -------------------------- |
| A. Workspace 메타 | 이 Workspace가 무엇인지 맥락 제공 | "내가 어디에 있지?"        |
| B. 팀 대시보드    | 팀 전체 상태 한눈에 보기          | "오늘 우리 팀 괜찮은가?"   |
| C. Agent 리스트   | 개별 Agent 탐색·관리              | "어느 Agent를 들여다볼까?" |
| D. 생성/초대 액션 | 새 Agent·멤버 추가                | "새로 만들자"              |

이 블록들은 위에서 아래로 A → B → C 순서로 배치하되, D는 A와 C 영역에 분산 배치한다.

---

## 📋 2. 블록 A: Workspace 메타 정보

### 2.1 무엇을 보여주는가

**필수 정보**:

- Workspace 이름 (예: "Customer Support")
- Workspace 아이콘 또는 이니셜

**보조 정보** (메타 라인으로):

- 소속 Agent 수 (예: "3 Agents")
- 멤버 수 (예: "12 Users")
- 생성일 (예: "Created Aug 15, 2024")

### 2.2 이 블록이 답하는 질문

- "지금 내가 어느 Workspace에 있지?"
- "이 Workspace는 얼마나 큰 규모지?"

### 2.3 설계 원칙

브레드크럼으로도 위치를 알 수 있지만, 페이지 본문 최상단에 한 번 더 명시한다. 브레드크럼은 작고 지나치기 쉬운 반면, Workspace Home은 **이 Workspace의 전용 공간**임을 시각적으로 선언해야 한다.

## 📊 3. 블록 B: 팀 대시보드

### 3.1 이 블록이 왜 필요한가

이전 화면(Org Home)에서도 일부 지표를 볼 수 있고, 다음 화면(Agent Overview)에서도 상세 지표가 있다. 그럼에도 Workspace Home에 대시보드가 필요한 이유는:

**"팀 관리자 관점의 유일한 대시보드"**이기 때문이다.

- Org Home은 여러 팀을 보여주기에 **개별 팀의 세부 상태는 약하게** 보임
- Agent Overview는 **Agent 하나**만 보여줌
- Workspace Home만이 **"이 팀 전체"**를 단일 뷰로 보여줄 수 있다

### 3.2 포함해야 하는 핵심 지표 (Tier 1)

다음 4개는 **반드시** 포함한다. 이 지표들은 "팀이 오늘 잘 돌아가고 있는가"를 판단하는 핵심 시그널이다.

#### 3.2.1 대화량 (Conversations Today)

- **표시값**: 오늘 이 Workspace 내 모든 Agent의 누적 대화 수
- **비교값**: 어제 같은 시각 대비 변화율 (±%)
- **데이터 범위**: Production 환경 대화만 (Dev/Staging 제외)
- **드릴다운**: 클릭 시 Agent별 분해 차트

**왜 중요한가**: 사용량의 갑작스런 증감은 외부 캠페인 효과, 장애, 또는 이상 트래픽의 신호다. 팀 리드가 가장 먼저 보는 지표.

#### 3.2.2 평균 CSAT (Customer Satisfaction)

- **표시값**: 이 Workspace Agent들의 가중 평균 만족도 (0~5)
- **비교값**: 어제 대비 변화 (±0.1 단위)
- **데이터 범위**: 지난 24시간
- **가중치**: Agent별 대화 수로 가중 평균

**왜 중요한가**: 품질의 핵심 지표. 하락은 즉시 개선 신호.

#### 3.2.3 활성 Agent 비율 (Active Agents)

- **표시값**: `{Prod 배포된 Agent 수} / {전체 Agent 수}` (예: "2 / 3")
- **보조값**: Dev 전용 Agent 수 (배포 전 작업 중인 개수)

**왜 중요한가**: 개발 중인 Agent가 오래 머물러 있으면 "왜 배포가 안 되고 있지?"를 촉발. 팀 생산성 지표.

#### 3.2.4 미해결 알림 수 (Alerts)

- **표시값**: 이 Workspace 내 미확인 알림 개수
- **분류**: Critical (에러), Warning (주의), Info
- **드릴다운**: 클릭 시 알림 패널 또는 Agent별 목록

**왜 중요한가**: "지금 당장 조치가 필요한가?"에 대한 직접적인 답.

### 3.3 포함하면 좋은 지표 (Tier 2)

공간이 허락하면 추가한다. 필수는 아님.

| 지표                         | 설명                                       |
| ---------------------------- | ------------------------------------------ |
| **해결률 (Resolution Rate)** | Agent가 에스컬레이션 없이 완결한 대화 비율 |
| **평균 응답 시간**           | 사용자 메시지 → Agent 응답까지 평균 초     |
| **에스컬레이션률**           | 인간 상담원으로 넘어간 비율                |
| **월간 사용량 소진률**       | Workspace 할당량 대비 사용률 (%)           |

### 3.4 포함하지 말아야 할 지표

아래는 Workspace Home에 부적합. 다른 화면으로 분리해야 한다.

| 지표             | 왜 부적합한가               | 대신 어디에?     |
| ---------------- | --------------------------- | ---------------- |
| 개별 대화 내용   | 너무 상세함                 | Agent > Evaluate |
| 토큰 사용량 통계 | 기술적 지표, 팀 운영과 거리 | Agent > Overview |
| 모델별 성능 비교 | 실험 성격                   | Agent > Evaluate |
| 멤버 개인별 활동 | 프라이버시 이슈             | Settings > Users |

### 3.5 데이터 범위와 시간 축

**기본 범위**:

- 시간 지표 (대화량, CSAT 등): 오늘 (00:00부터 현재까지)
- 비교 기준: 어제 같은 시각

**범위 전환 옵션** (선택):

- 오늘 / 지난 24시간 / 지난 7일 / 지난 30일
- 팀 리드가 리뷰 주기에 맞춰 조정할 수 있도록

### 3.6 빈 상태 처리

**Agent 0개인 경우**: 이 블록 자체를 렌더링하지 않는다. 보여줄 지표가 없기 때문.

**대화 데이터 0건인 경우** (Agent는 있지만 배포 안 됨): "아직 데이터가 없습니다. Agent를 배포하면 여기에 지표가 표시됩니다" 플레이스홀더.

## 🤖 4. 블록 C: Agent 리스트

### 4.1 설계 원칙: "각 Agent 카드는 Agent Overview의 미리보기다"

사용자가 카드만 보고도 "이 Agent를 들여다볼 필요가 있는지" 판단할 수 있어야 한다. 이름과 아이콘만으로는 부족하다.

### 4.2 각 Agent가 포함해야 하는 정보

아래 정보들을 **카테고리별로** 구분해 설명한다. 카드 UI에서 어떻게 표현할지는 자율이지만, **정보 자체는 모두 포함**해야 한다.

#### 카테고리 1: 정체성 (Identity)

Agent를 식별하는 정보.

| 필드   | 필수 여부 | 설명                                 |
| ------ | --------- | ------------------------------------ |
| 이름   | 필수      | Agent의 표시 이름                    |
| 아이콘 | 필수      | 이미지 또는 이모지, 없으면 이니셜    |
| 설명   | 선택      | 한 줄 (없으면 "설명 없음" 또는 생략) |

#### 카테고리 2: 배포 상태 (Deployment)

"이 Agent는 어디에 배포되어 있는가?"

- **각 환경(Dev/Staging/Prod)의 배포 여부**: 3개 환경을 개별적으로 표시
- **각 환경의 버전**: 예) Prod v0.38 (선택, 공간 허락 시)
- **어느 환경에도 배포되지 않은 상태 표시**: "Not deployed" 또는 "개발 중"

이 정보가 없으면 팀 리드는 "이 Agent가 실제 서비스 중인가?"를 알 수 없다.

#### 카테고리 3: 운영 지표 (Operational Metrics)

"이 Agent는 잘 돌아가고 있는가?" — 이것이 카드의 **가장 중요한 정보**다.

| 지표                       | 우선순위 | 설명                   | 조건                 |
| -------------------------- | -------- | ---------------------- | -------------------- |
| 지난 7일 대화 수           | 높음     | Prod 환경 기준         | Prod 배포된 경우만   |
| CSAT                       | 높음     | 지난 7일 평균          | 데이터 있는 경우만   |
| 해결률 또는 에스컬레이션률 | 중       | 선택 1개               | 데이터 있는 경우만   |
| 알림 수                    | 높음     | 이 Agent의 미해결 알림 | 1개 이상일 때만 표시 |

**지표가 없을 때 처리**:

- 배포 전 Agent: "Not deployed" 명시, 지표 영역 공백 또는 "—"
- 배포됐지만 데이터 없음: 각 지표를 "—"로 표시
- **절대 "0"으로 표시하지 말 것**. "0"은 실제 0과 데이터 없음이 구분되지 않음

#### 카테고리 4: 건강 상태 (Health Signal)

지표를 본 후 "주목할 필요가 있는가"를 빠르게 판단할 수 있도록.

- **정상(healthy)**: 특별 표시 없음 또는 녹색 점
- **경고(warning)**: 노란 표시 (예: CSAT가 기준치 이하로 떨어짐, 응답 시간 증가)
- **오류(error)**: 빨간 표시 (예: 에러율 급증, 서비스 중단)
- **알 수 없음(unknown)**: 회색 (Not deployed 또는 데이터 부족)

이 상태는 여러 지표를 조합한 **종합 판단**이며, 별도 알고리즘이나 임계값 설정이 필요. 초기에는 단순 규칙으로 시작해도 됨 (예: "alertCount > 0이면 warning").

#### 카테고리 5: 관리 메타 (Management Metadata)

"누가 언제 무엇을 했는가" — 협업 맥락.

| 필드           | 설명                                             |
| -------------- | ------------------------------------------------ |
| 최종 수정 시각 | 상대 시간 ("2 hours ago") 또는 절대 시각         |
| 최종 수정자    | 이름 또는 아바타                                 |
| 생성일         | 신규 Agent 식별용 (선택, "New" 뱃지로 대체 가능) |

이 정보는 협업 중 "누가 건드렸지?"를 묻기 전에 답해준다.

### 4.3 카드에서 제공해야 하는 인터랙션

| 동작           | 목적지 / 효과                                                   |
| -------------- | --------------------------------------------------------------- |
| 카드 본체 클릭 | Agent Overview로 이동 (기본은 Production, 미배포면 Development) |
| 환경 표시 클릭 | 해당 환경의 Overview로 직접 진입                                |
| 알림 표시 클릭 | 알림 상세 또는 Evaluate 화면                                    |
| 관리 메뉴 (⋯)  | Rename, Duplicate, Archive, Delete 등                           |

**중요**: 카드 안에 여러 클릭 타겟이 있으므로, 각 타겟이 독립적으로 동작해야 한다 (이벤트 버블링 처리 필요).

### 4.4 리스트 수준의 도구

개별 카드가 아니라 "리스트 전체"에 걸친 기능.

#### 4.4.1 검색

- **검색 범위**: Agent 이름, 설명
- **실시간 필터**: 타이핑하는 즉시 결과 좁힘
- **빈 결과 처리**: "검색 결과 없음" 명시 + 필터 초기화 버튼

#### 4.4.2 필터

다음 기준으로 필터링할 수 있어야 한다.

| 필터      | 옵션                               |
| --------- | ---------------------------------- |
| 배포 상태 | All / Prod 배포됨 / Dev만 / 미배포 |
| 건강 상태 | All / 정상 / 경고 / 오류           |
| 알림 유무 | All / 알림 있음만                  |

#### 4.4.3 정렬

| 정렬 기준                     | 기본 여부            |
| ----------------------------- | -------------------- |
| 최종 수정일 (최신순)          | ✅ 기본값            |
| 이름 (A-Z)                    |                      |
| 생성일 (최신순)               |                      |
| 대화량 (많은 순)              |                      |
| 건강 상태 (문제 있는 것 먼저) | 운영자 관점에서 유용 |

**기본값이 "최종 수정일"인 이유**: 가장 최근 작업한 Agent가 관심 대상일 확률이 높음.

#### 4.4.4 뷰 전환

- **카드 뷰**: 시각적, 스캔 용이. 기본값.
- **리스트(테이블) 뷰**: 많은 Agent를 한 번에 비교할 때

Agent가 10개를 넘어가면 리스트 뷰의 효용이 커진다.

### 4.5 빈 상태 분기

Agent 리스트의 빈 상태는 **두 종류**로 구분해야 한다.

#### 4.5.1 Agent가 아예 없는 경우 (신규 Workspace)

- 메시지: "첫 번째 Agent를 만들어보세요"
- 설명: 이 제품으로 무엇을 할 수 있는지 한 줄 안내
- CTA: "+ New Agent" (주요), "템플릿 둘러보기" (보조)

#### 4.5.2 필터로 인한 빈 결과

- 메시지: "검색/필터 결과가 없습니다"
- 설명: 어떤 필터가 적용됐는지 요약 (예: "'foo'에 대한 결과 없음")
- CTA: "필터 초기화"

두 상태는 **완전히 다른 메시지와 CTA**를 가져야 한다. 혼동하지 말 것.

## ➕ 5. 블록 D: 생성/초대 액션

### 5.1 배치 위치

액션 버튼은 한 곳에 몰지 않고 **사용자가 필요한 순간에 만나도록** 분산 배치한다.

| 액션                 | 위치                     | 이유                              |
| -------------------- | ------------------------ | --------------------------------- |
| + New Agent          | 페이지 상단 우측 (헤더)  | 메인 CTA, 언제든 접근             |
| + New Agent          | Agent 리스트 마지막 카드 | 리스트를 스크롤한 뒤에도 보이도록 |
| + Invite Members     | 페이지 상단 (헤더)       | 팀 확장 맥락                      |
| ⚙ Workspace Settings | 페이지 상단 (헤더)       | 설정 빠른 진입                    |

### 5.2 Agent 생성 플로우에서 수집할 정보

생성 다이얼로그는 3단계로 구성하되, 각 단계에서 수집하는 정보는 다음과 같다.

#### Step 1: 정체성

- Agent 이름 (필수)
- 설명 (선택)
- 아이콘 (이모지 선택 또는 업로드)

#### Step 2: 시작 템플릿

빈 상태로 시작할지, 프리셋에서 시작할지 선택.

- Blank (빈 상태)
- Customer Support (FAQ + 주문 조회)
- Sales Lead (자격 검증 대화)
- Onboarding
- HR
- Custom Import (기존 설정 파일 업로드)

#### Step 3: 초기 환경

- 활성화할 환경 체크박스
  - Development (기본 체크, 해제 불가)
  - Staging (선택)
  - Production (선택, 체크 시 경고: "즉시 실사용자에게 노출됩니다")
- 기본 모델 선택
- 기본 언어 선택

### 5.3 생성 후 동작

Agent 생성 성공 시 **자동으로 새 Agent의 Build 화면 (Development 환경)으로 이동**한다. 사용자는 방금 만든 Agent를 바로 편집하기 시작할 수 있어야 한다.

## 🔗 6. 다른 화면과의 관계

Workspace Home은 다음 화면들의 **허브** 역할을 한다.

### 6.1 위로 (상위 계층)

- **Org Home (Entry)**: 다른 Workspace로 이동하려면 이곳을 거침
- **Workspace Switcher** (사이드바): Org Home 경유 없이 다른 WS로 직행

### 6.2 아래로 (하위 계층)

- **Agent 내부 화면**: 카드 클릭으로 진입
- **Workspace Settings**: 헤더의 ⚙ 버튼 또는 사이드바 메뉴

### 6.3 횡적 (병렬 화면)

- **Profile / Notifications**: 개인 영역은 전역 네비에서

### 6.4 정보의 일관성

같은 지표가 여러 화면에 나타날 때 **값이 일치**해야 한다.

- Workspace Home의 "Support Bot 대화 수" = Support Bot Agent Overview의 "대화 수"
- 단, **시간 범위**가 다를 수 있으니 명시 필요 (예: Home은 7일, Overview는 오늘)

## 📦 7. 데이터 요구사항

### 7.1 필요한 데이터 엔티티

이 화면을 그리기 위해 필요한 데이터.

#### Workspace (메타)

- id, name, slug, iconUrl, createdAt, memberCount

#### TeamMetrics (집계 지표)

- conversationsToday: { value, changePercent }
- avgCsat: { value, change }
- activeAgents: { active, total }
- alertCount: { critical, warning, info }
- (선택) resolutionRate, avgResponseTime, escalationRate, usagePercent

#### Agent List

각 Agent마다:

- 정체성: id, name, slug, description, iconUrl
- 배포 상태: environments.{development, staging, production}.{deployed, version, deployedAt}
- 운영 지표: metrics.{conversationsLast7Days, csat, resolutionRate, alertCount}
- 건강 상태: health (healthy | warning | error | unknown)
- 관리 메타: lastEditedAt, lastEditedBy, createdAt, status (active | archived)

### 7.2 집계 데이터의 신선도

| 지표                   | 갱신 주기       | 허용 지연 |
| ---------------------- | --------------- | --------- |
| 대화량, CSAT           | 실시간 또는 1분 | 5분까지   |
| 해결률, 에스컬레이션률 | 5분             | 15분까지  |
| 알림                   | 즉시            | 1분까지   |

### 7.3 권한에 따른 데이터 노출

| Role          | Team Metrics | Agent List  | Agent 지표  | 관리 액션   |
| ------------- | ------------ | ----------- | ----------- | ----------- |
| Owner / Admin | 전체         | 전체        | 전체        | 전체        |
| Editor        | 전체         | 전체        | 전체        | 생성/편집만 |
| Viewer        | 전체 (읽기)  | 전체 (읽기) | 전체 (읽기) | 없음        |

## 🔄 8. 상태 및 분기 처리

### 8.1 로딩 상태

세 블록이 **독립적으로 로딩**되어야 한다. Team Metrics가 느리게 온다고 Agent 리스트가 차단되면 안 됨.

- Workspace 메타: 가장 빠름 (라우팅 정보 기반)
- Team Metrics: 집계 쿼리, 수 초 가능
- Agent List: 중간

### 8.2 빈 Workspace (Agent 0개)

- 메타 블록: 정상 표시
- Team Metrics 블록: **완전히 숨김** (보여줄 것 없음)
- Agent 리스트 블록: EmptyState

### 8.3 권한 부족 (접근 불가)

- 403 화면 표시
- 메시지: "이 Workspace에 접근할 권한이 없습니다"
- CTA: "Organization Home으로" 또는 "관리자에게 요청"

### 8.4 Workspace 아카이브 상태

아카이브된 WS는 접근은 가능하되 읽기 전용.

- 상단에 배너: "이 Workspace는 아카이브되었습니다. Agent 실행이 정지되어 있습니다."
- 생성/편집 버튼 모두 비활성화
- Unarchive 버튼 (권한 있는 경우) 제공

### 8.5 할당량 초과

Usage Quota 초과 시:

- 배너: "이 Workspace의 월간 한도에 도달했습니다"
- Agent들은 계속 표시되지만 실서비스 중단됐을 수 있음을 알림
- Team Metrics의 사용량 지표 강조

## ✅ 9. 정보 설계 체크리스트

구현 후 검증할 항목.

### 9.1 정보 완전성

- [ ] Workspace 메타 정보가 모두 표시됨 (이름, 메타 라인)
- [ ] Team Metrics Tier 1 지표 4개가 모두 포함됨
- [ ] 각 Agent 카드에 5개 카테고리 정보가 모두 포함됨
  - [ ] 정체성 (이름, 아이콘)
  - [ ] 배포 상태 (3개 환경)
  - [ ] 운영 지표 (대화량, CSAT 등)
  - [ ] 건강 상태
  - [ ] 관리 메타 (최종 수정 시각·수정자)

### 9.2 데이터 정확성

- [ ] "0"과 "—"(데이터 없음)이 구분됨
- [ ] 변화율 계산이 명확 (무엇 대비 무엇인지)
- [ ] 가중 평균 CSAT의 가중치 기준이 문서화됨
- [ ] 시간 범위가 지표마다 명시됨

### 9.3 빈 상태·예외

- [ ] Agent 0개 → Team Metrics 숨김 + Agent EmptyState
- [ ] 검색 결과 0건 → NoResultsState (EmptyState와 다른 메시지)
- [ ] 배포 전 Agent → "Not deployed" 명시
- [ ] 데이터 없음 → "—" 처리

### 9.4 인터랙션

- [ ] 카드 본체 클릭 → Prod Overview (미배포 시 Dev)
- [ ] 환경 표시 클릭 → 해당 환경으로 직행
- [ ] 알림 표시 클릭 → 알림 상세
- [ ] 검색/필터/정렬 작동

### 9.5 권한

- [ ] Viewer는 생성·편집 버튼이 숨겨짐 (또는 비활성화)
- [ ] 아카이브 상태에서 편집 차단
- [ ] 할당량 초과 시 배너 표시

### 9.6 정보 일관성

- [ ] 사이드바 Agent 목록과 리스트 블록의 Agent가 일치
- [ ] 카드의 지표 시간 범위(7일)가 명시됨
- [ ] 아이콘이 없는 Agent에 대한 폴백 처리 (이니셜)

## 🚫 10. 이 화면에 포함하지 말아야 할 것

흔히 저지르는 과잉 설계를 방지하기 위한 금지 목록.

### 정보 과잉

- ❌ 각 Agent의 시간대별 대화량 차트 (Agent Overview로)
- ❌ 멤버별 활동 로그 (Settings > Users로)
- ❌ 토큰/비용 상세 내역 (Billing 또는 Agent Overview로)
- ❌ 개별 대화 내용 미리보기 (Evaluate로)

### 기능 과잉

- ❌ 여기서 Agent 편집 가능하게 (Build 화면으로 가야 함)
- ❌ 여기서 환경 Promote 실행 (Agent 화면으로)
- ❌ 여기서 실시간 대화 모니터링 (별도 화면)

### 시각적 과잉

- ❌ Agent마다 큰 차트 넣기 (스캔 방해)
- ❌ Team Metrics를 대시보드 전체처럼 확장 (Org Home 영역)

**판단 기준**: "팀 리드가 5초 안에 상황 파악할 수 있는가?" 그 목표를 방해하는 것은 모두 제외.
