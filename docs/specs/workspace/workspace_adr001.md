# ADR-001: Workspace Home에서 Agent의 환경 상태를 어떻게 표시할 것인가

> **ADR 번호**: 001
> **제목**: Workspace Home의 Agent 카드 환경 표시 방식
> **상태**: Accepted (채택됨)
> **결정일**: 2026-04-22
> **결정자**: UX Design
> **관련 문서**: WORKSPACE_HOME_INFO_GUIDE.md, WORKSPACE_SPEC.md

---

## 📌 컨텍스트 (Context)

### 배경

Delight.ai 대시보드의 각 AI Agent는 Development / Staging / Production 3개 환경에서 **동시에 공존**한다. 즉, 같은 Agent라도:

- Dev에는 v0.42 (개발 중)
- Staging에는 v0.41 (QA 중)
- Prod에는 v0.38 (실서비스)

처럼 서로 다른 버전이 각 환경에 배포되어 있을 수 있다.

Workspace Home 화면의 Agent 카드에서 이 환경별 상태를 어떻게 시각화할지에 대한 결정이 필요하다.

### 이 결정이 중요한 이유

Workspace Home은 팀 단위 Agent 운영의 허브 화면이다. 이 화면에서 환경 상태를 어떻게 보여주느냐에 따라:

- 사용자가 **"지금 우리 팀 상태"를 얼마나 빠르게 파악**할 수 있는가
- 카드의 **인지 부하**가 낮은가 높은가
- **여러 페르소나의 서로 다른 관심사**를 동시에 만족시킬 수 있는가

가 결정된다.

### 충돌하는 요구사항

| 요구사항             | 주장자    | 근거                                                  |
| -------------------- | --------- | ----------------------------------------------------- |
| 3개 환경을 모두 표시 | 원 설계안 | 배포 파이프라인 전체 흐름이 핵심이므로 다 보여야 함   |
| Production만 표시    | 검토 의견 | 어차피 실서비스는 Prod이므로, Dev/Staging은 정보 과잉 |

두 주장 모두 일리가 있어, 본 ADR을 통해 최종 결정한다.

---

## 🎯 결정 (Decision)

### 채택안: **Production 중심, Dev/Staging 보조 표시 (계층적 정보 노출)**

Agent 카드의 시각적 중심은 **Production 상태**로 하되, Dev/Staging 정보는 **축약된 형태로 보조적으로** 노출한다.

### 구체 규칙

#### 규칙 1: 메인 표시는 Production

Agent 카드에서 가장 강조되는 정보는 Production 환경의 상태와 지표다.

- Prod 배포 버전 (예: `v0.38`)
- Prod 건강 상태 (healthy/warning/error)
- Prod 운영 지표 (지난 7일 대화 수, CSAT, 알림 수)

이 정보들이 **카드에서 가장 눈에 띄게** 배치된다.

#### 규칙 2: Dev/Staging은 축약 요약

Dev와 Staging은 "버전 + 간단한 상태" 정도로만 축약 표시.

- 예: `Dev v0.42 · Staging v0.41`
- 배포되지 않은 환경은 **생략** (공간 차지 금지)
- Prod와 동일 버전인 환경도 **생략 가능** (파이프라인 안정 상태)

#### 규칙 3: Prod 미배포 시 폴백

Production에 아직 배포되지 않은 Agent는 다음 우선순위로 메인 표시를 대체.

```
Prod 미배포 → Staging을 메인 표시 (있을 경우)
Staging도 없음 → Dev를 메인 표시
Dev도 없음 → "Not deployed" 빈 상태
```

이 경우 메인 표시 영역에 명확히 "Staging" 또는 "Development" 레이블 병기.

#### 규칙 4: 파이프라인 신호 (선택적)

환경 간 상태 차이가 있을 때, 팀 운영에 의미 있는 신호를 추가 노출한다.

| 상황                       | 신호 예시                                     |
| -------------------------- | --------------------------------------------- |
| Dev 버전 > Prod 버전       | `↑ 업데이트 대기 중 (Dev v0.42 → Prod v0.38)` |
| Staging에 새 버전 있음     | `⏳ QA 검증 대기`                             |
| Dev에서 오래 머무름 (7일+) | `⏸ 배포 지연`                                 |
| 모든 환경 동일 버전        | 신호 없음 (안정 상태)                         |

이 신호는 선택적으로 도입하며, 팀 리드의 의사결정에 직접 도움이 되는 정보에만 한정한다.

#### 규칙 5: Team Metrics는 Production 기준 고정

Workspace Home 상단의 Team Metrics(대화량, CSAT, 알림)는 **Production 환경 데이터만** 집계한다. Dev/Staging 데이터와 섞지 않는다. 시간 범위 및 환경 범위를 UI에 명시한다.

## 🔄 검토한 대안들 (Alternatives Considered)

### 대안 A: 3개 환경 동등 표시 ❌

원 설계안. 각 Agent 카드에 `[DEV][STG][PROD]` 3개 뱃지를 동등한 시각 무게로 표시.

**장점**:

- 배포 파이프라인 전체를 한눈에 볼 수 있음
- 모든 페르소나(Builder/Validator/Operator)에게 공평한 정보

**단점**:

- **정보 과잉**: 한 카드에 환경 3개 × 각각의 버전/지표 = 최대 9개 정보 단위
- **시각적 중요도 무력화**: 셋 다 강조하면 아무것도 강조 안 된 것과 같음
- **실제 사용 빈도 무시**: 대다수 사용자는 Prod가 주 관심사인데, Dev/Staging과 동등하게 취급
- 카드 크기가 비대해지거나, 정보를 작게 욱여넣어 가독성 저하

**기각 이유**: 정보 과잉으로 인해 "5초 안에 상황 파악"이라는 Workspace Home의 설계 목표를 방해.

### 대안 B: Production만 표시 ❌

검토 의견으로 제시된 안. Dev/Staging 정보는 Agent 카드에서 완전히 제외하고, Production 상태만 표시.

**장점**:

- 카드가 매우 깔끔함
- 운영자(Operator) 페르소나에게 최적
- 구현 복잡도 최저

**단점**:

- **개발자(Builder)와 QA(Validator) 페르소나에게 정보 부족**
- **파이프라인 흐름 상실**: 이 제품의 핵심 가치는 Dev → Staging → Prod 흐름인데, 이걸 가리면 제품 철학과 불일치
- **배포 지연 감지 불가**: "Dev에서 3일째 머물러 있다" 같은 팀 운영 문제를 Workspace Home에서 발견할 수 없음
- **신규/개발 중 Agent가 숨겨짐**: Prod 미배포 Agent는 "없는 것처럼" 보임

**기각 이유**: Workspace Home의 역할 중 "팀 운영 모니터링"이 크게 약화됨. Builder/Validator 페르소나에게 가치를 제공하지 못함.

### 대안 C: 사용자 역할별 모드 전환 ❌

사용자 프로필에 따라 "운영자 뷰 / 개발자 뷰 / 팀장 뷰"를 전환.

**장점**:

- 각 페르소나에게 최적화된 정보 제공

**단점**:

- **학습 곡선**: 사용자가 모드 개념 자체를 학습해야 함
- **구현 복잡도 증가**: 여러 뷰의 유지보수 부담
- **같은 팀원 간 소통 어려움**: "여기 Support Bot에 뭐가 떠 있어?" "어느 뷰에서?"
- 과제 요구사항 대비 과한 복잡도

**기각 이유**: 복잡도 대비 이득이 불분명. MVP에는 부적합.

### 대안 D: Prod + 마지막 활동 환경 표시 △

Production 상태를 메인으로 보여주되, 최근 활동이 있었던 환경 하나를 추가로 표시.

**장점**:

- 최근 작업 중인 환경을 자연스럽게 노출
- 정보 밀도가 적절

**단점**:

- "최근 활동"의 정의가 모호 (어느 수준의 활동?)
- 파이프라인 전체 상태는 여전히 안 보임
- Staging만 중요한 QA 입장에서는 Dev 활동이 표시될 수 있어 혼란

**기각 이유**: 정보 선택 로직이 모호해 예측 가능성이 낮음. 채택안(계층적 노출)이 더 명확.

### 대안 E: Prod 중심 + 접기/펼치기 △

Production만 기본 표시하되, 카드에 "환경 상세 보기" 토글로 Dev/Staging을 펼쳐볼 수 있게 함.

**장점**:

- 기본은 깔끔하고 필요시 상세 확인 가능

**단점**:

- **추가 클릭 필요**: 파이프라인 파악에 매번 펼쳐야 함
- **카드가 가변 높이**: 리스트 레이아웃 깨짐
- "이 Agent 펼쳐놨던가?" 상태 관리 피로

**기각 이유**: 사용자 동작을 강제하므로 스캔성 저하. 채택안이 "보이는 정보 양"과 "스캔 용이성"의 균형이 더 나음.

## 🎯 결정의 근거 (Rationale)

### 1. 페르소나별 니즈를 동시에 만족

| 페르소나          | 주 관심         | 채택안에서 어떻게 만족되는가                       |
| ----------------- | --------------- | -------------------------------------------------- |
| Operator (운영자) | Production 상태 | **메인 표시가 Prod**이므로 즉시 파악               |
| Builder (개발자)  | Dev 상태        | **축약된 Dev 정보**로 맥락 확보, 상세는 Agent 진입 |
| Validator (QA)    | Staging 상태    | **축약된 Staging 정보** + 검증 대기 신호           |
| Admin (팀장)      | 파이프라인 전체 | **규칙 4의 파이프라인 신호**로 흐름 파악           |

한 뷰에서 모든 페르소나가 **최소한의 핵심 정보**는 얻을 수 있다.

### 2. 시각적 위계가 실제 중요도를 반영

UX의 기본 원칙은 "**중요한 것은 크게, 덜 중요한 것은 작게**"다. 실사용자에게 영향을 주는 것은 Production이고, Dev/Staging은 "그 과정"이다. 이 위계를 시각적으로 반영한다.

### 3. "흐름"의 본질을 해치지 않음

대안 B(Prod만)의 근본 문제는 **이 제품의 핵심 가치인 "환경 파이프라인"을 UI에서 지워버리는** 것이다. 채택안은 Prod를 강조하면서도 파이프라인을 축약된 형태로 유지한다.

### 4. 정보 밀도의 균형

| 항목              | 대안 A      | 대안 B   | **채택안**    |
| ----------------- | ----------- | -------- | ------------- |
| 정보 단위 (개)    | 9           | 3        | **5-6**       |
| 스캔 용이성       | 낮음        | 높음     | **중간-높음** |
| 파이프라인 가시성 | 높음        | 없음     | **중간**      |
| 페르소나 커버리지 | 모두 (얕게) | 운영자만 | **모두**      |

### 5. 점진적 개선 여지

채택안은 MVP로 충분하며, 향후 사용자 피드백에 따라:

- 파이프라인 신호(규칙 4)를 더 지능화
- 사용자 설정으로 "항상 펼쳐 보기" 옵션 제공
- 역할 기반 뷰(대안 C)로 확장

등이 가능하다. 대안 B를 채택했다면 나중에 Dev/Staging 정보를 "되돌려 넣는" 것은 오히려 어렵다.

## 📊 적용 예시

### 케이스 1: 모든 환경이 안정 상태 (Prod와 Dev/Staging 버전 동일)

```
🤖 Support Bot
고객 지원 문의 처리

🟢 PRODUCTION · v0.38
💬 12,483 conversations (7d)
😊 CSAT 4.6

Last edit: Jiyong, 2h ago
```

Dev/Staging 라인은 **생략** (Prod와 같은 버전이므로 노이즈).

### 케이스 2: Dev에 새 버전, 아직 승격 전

```
🤖 Support Bot
고객 지원 문의 처리

🟢 PRODUCTION · v0.38
💬 12,483 conversations (7d)
😊 CSAT 4.6

↑ 업데이트 대기 중: Dev v0.42 → Prod
Dev v0.42 · Staging v0.41

Last edit: Jiyong, 2h ago
```

Dev/Staging 라인 노출 + 파이프라인 신호(`↑ 업데이트 대기`).

### 케이스 3: Prod 미배포 (Dev만 있음)

```
🤖 Onboarding
신규 가입 고객 안내

⚪ Not deployed to Production
Development · v0.01

⏸ 개발 중 (5일 전부터)

Last edit: David, 5d ago
```

Prod 메인 표시 자리에 "Not deployed" + 다음 환경으로 폴백.

### 케이스 4: Staging에서 QA 대기 중

```
🤖 FAQ Helper
자주 묻는 질문 응대

🟢 PRODUCTION · v0.14
💬 3,240 conversations (7d)
😊 CSAT 4.4

⏳ QA 검증 대기: Staging v0.15
Dev v0.15 · Staging v0.15

Last edit: Sarah, 1d ago
```

Prod 메인 + 파이프라인 신호(`⏳ QA 대기`).

## 🔀 결과 및 영향 (Consequences)

### 긍정적 영향

- 모든 페르소나가 한 뷰에서 최소한의 핵심 정보를 얻음
- 시각적 위계가 명확해 스캔 속도 향상
- 제품의 핵심 가치(배포 파이프라인)가 UI에 반영됨
- 향후 확장 여지 확보

### 부정적 영향 (트레이드오프)

- **구현 복잡도 증가**: 환경별 조건 분기 로직 필요 (대안 B 대비)
- **디자인 가이드 엄격화**: "무엇을 크게, 무엇을 작게" 규칙이 명확해야 일관성 유지
- **QA 케이스 증가**: 환경 조합별 표시 케이스 다수 (위 예시 4가지 이상)

### 후속 작업 필요

1. **WORKSPACE_HOME_INFO_GUIDE.md 업데이트**: §4.2 카테고리 2 (배포 상태) 재작성
2. **AgentCard 컴포넌트 명세 업데이트**: 환경 표시 우선순위 로직 반영
3. **파이프라인 신호 정의 문서**: 규칙 4의 신호들을 어떤 조건에서 표시할지 구체화 필요
4. **디자인 토큰**: "메인 표시 환경 색상" vs "축약 표시 색상" 차등 정의

### 모니터링 지표

이 결정이 옳았는지 검증할 지표:

- Workspace Home에서 Agent Overview로의 클릭 전환율
- 사용자 체류 시간 (너무 짧으면 정보 부족, 너무 길면 정보 과잉)
- "Dev에서 오래 머무는 Agent"가 실제로 빨리 배포되는지 (파이프라인 신호 효과)
